## Task 4.2: Improve Database Connection Handling
**Location:** `backend/database.ts`, `backend/database_worker.ts`
**Objective:** Eliminate single-threaded bottleneck, add query timeouts, modernize SQLite patterns.

### 4.2.1 Enable WAL Mode
**File:** `backend/database_worker.ts`
- Change: `db.pragma('journal_mode = DELETE')` → `db.pragma('journal_mode = WAL')`
- Add: `db.pragma('synchronous = NORMAL')`
- Add: `db.pragma('cache_size = -64000')` (64MB cache)
- Add: `db.pragma('busy_timeout = 5000')` (5s timeout)

### 4.2.2 Add Query Timeout Mechanism
**File:** `backend/database.ts`
- Add timeout tracking to `pendingRequests` map with timestamps
- Implement 30-second timeout per query
- Reject promises on timeout with cleanup
- Add abort capability via AbortController pattern

**File:** `backend/database_worker.ts`
- Wrap query execution in try-catch with timeout awareness
- Ensure proper error propagation

### 4.2.3 Modern SQLite Patterns
**File:** `backend/database_worker.ts`
- Replace try/catch ALTER TABLE with IF NOT EXISTS clauses (lines 124-125)
- Add schema version tracking table
- Implement migration system with version checks
- Use `CREATE TABLE IF NOT EXISTS` consistently (already done)

## Task 4.3: Add Health Check Endpoints
**Location:** `backend/api/routes.ts`
**Objective:** Add Kubernetes/orchestration-friendly health endpoints.

### 4.3.1 Liveness Endpoint
**Endpoint:** `GET /health`
- Returns 200 if process is running
- Include: timestamp, version, uptime
- No external dependencies (no DB checks)
- Place before rate limiter or exempt from it

### 4.3.2 Readiness Endpoint  
**Endpoint:** `GET /ready`
- Checks database connectivity (test query)
- Verifies trading engine status
- Returns 503 if dependencies unavailable
- Include: db status, engine status, timestamp

### 4.3.3 Startup Probe Endpoint
**Endpoint:** `GET /startup`
- Verifies critical services initialized
- Returns 200 when ready to serve traffic
- Include: startup diagnostics, service states

## Task 4.4: Enhance Logging Configuration
**Location:** `backend/logging/logger.ts` (lines 13-19)
**Objective:** Proper log level enforcement, structured logging, log rotation.

### 4.4.1 Improve Log Level Parsing
- Default to 'info' in production (NODE_ENV === 'production')
- Default to 'debug' in development
- Validate against allowed levels: debug, info, warn, error
- Case-insensitive parsing

### 4.4.2 Add Structured Logging
- JSON format for production (already implemented)
- Include request correlation IDs (already have getRequestId)
- Add service name to all logs (context.service already supported)
- Add hostname/pid for distributed tracing
- Standardize field names

### 4.4.3 Configure Log Rotation
- Implement size-based rotation (e.g., 10MB per file)
- Implement time-based rotation (daily)
- Archive old logs with timestamp
- Prevent disk space issues with max file count
- Consider using external log rotation (logrotate) or implement in-process
